## CRITICAL（矛盾——必须在实现前解决）

### C1. `port_auto_fallback` max retries 不一致

| 文档 | 值 |
|------|-----|
| `04-config.md` §3.2 L2 约束 | **最多重试 3 次** |
| `03-daemon/port-conflict.md` §3.2 | `max_attempts = 10` |

**L3 必须遵从 L2 约束。** 应统一值。

---

### C2. `/turn/tool` role 字段矛盾

| 文档 | role 值 |
|------|---------|
| `03-daemon/sqlite-schema.md` §2.3 | `role TEXT NOT NULL` — `'user' | 'tool'` |
| `05-capture/hook-flow.md` §2.2 step 2 | `role = "assistant"` |

以 sqlite-schema.md 为权威定义——hook-flow.md 应写 `role = "tool"`。

---

### C3. `sessions` 表缺少 `buffered_chars` 列

`05-capture/hook-flow.md` §1.2 step 3 引用了 `sessions.buffered_chars` 列，但 `03-daemon/sqlite-schema.md` §2.2 的 sessions 表定义中不存在此列。hook-flow 自身的阈值计数器是内存变量（§1.3），此 DB 列并非必需。

---

### C4. `schema_version` vs `schema_versions` 表名不一致

| 文档 | 表名 |
|------|------|
| `03-daemon/sqlite-schema.md` §2.1 | `schema_version`（单数） |
| `10-deployment/upgrade.md` §4 | `schema_versions`（复数） |

以 sqlite-schema.md 为权威定义。统一为单数。

---

### C5. `upgrade.md` migration 伪代码 schema 与 sqlite-schema.md 不符

`10-deployment/upgrade.md` §4 中的 sessions 表多了 `started_at`（应为 `created_at`）、`topic_scope`（不存在）、`buffered_chars`（不存在），且缺少 `closed_at`。turns 表同样用 `content TEXT NOT NULL`, `tool_calls TEXT`（应为 `content TEXT`, `tool_name`, `tool_arguments`, `tool_output`）。

upgrade.md 应直接从 sqlite-schema.md 引用 DDL，不重复定义。

---

### C6. `/bible-cc:push` 端点 `POST /daemon/session/flush` 未定义

`07-commands/specs.md` 引用 `POST /daemon/session/flush`，但 `02-interfaces.md` 和 `03-daemon/http-api.md` 中均无此端点。需要在接口 spec 中新增端点定义，或修改 commands/specs.md 指向已有端点。

---

### C7. `/daemon/health` 响应缺少 `pid`/`port`

`08-operability/status.md` 的 `/bible-cc:status` 输出展示了 pid 和 port，并说明数据来自 `GET /daemon/health`。但 `03-daemon/http-api.md` §2.3 的 health response schema 不含 `pid` 和 `port` 字段。

---

### C8. `detection.model` 解析优先级与 config 系统通用规则矛盾

`04-config.md` §3.6 L2 约束暗示 env var 优先（`ANTHROPIC_SMALL_FAST_MODEL` 优先），但 `04-config/schema.md` §2.6 的 `resolve_detection_model()` 将 **config 置于 env var 之前**：

```python
config_model or os.getenv("ANTHROPIC_SMALL_FAST_MODEL") or os.getenv("ANTHROPIC_MODEL") or "claude-sonnet-4-5"
```

这违反了 config 系统的通用覆盖规则（env > file > default）。

## HIGH（可能导致实现问题）

### H1. Phase 2 `max_tokens=1024` 不可配置

`05-capture/detection.md` §5 规定 Phase 2 用 `max_tokens=1024`，但 `04-config/schema.md` 的 `detection.max_tokens` 只有一个默认值 `512`。

### H2. `capture.hint_format` / `inject_fallback` 缺少 Pydantic validator

`04-config.md` L2 约束要求非法值 fallback，但 `04-config/schema.md` Pydantic model 中缺少对应的 `@field_validator`。

### H3. Hook 中途 crash 的"重试一次"行为未在接口 spec 中定义

`08-operability/failure-paths.md` F2 说 hooks "尝试重启一次（POST /daemon/start，一次）"，但 `02-interfaces.md` §4.1 的 Hook 失败行为表中 UserPromptSubmit/PostToolUse 是"静默跳过"。

### H4. Knowledge-base search tag 硬编码为 `"design"`

`06-recall/consult.md` §4 硬编码 `tag="design"`（注释说"可通过 config 覆盖"），但 `04-config.md` 未定义对应的配置项。

### H5. `bible_memory_save` 的 `messages[]` 序列化未设计

`02-interfaces.md` §3 和 `06-recall/mcp-tools.md` 提到 `bible_memory_save` 接受 `messages[]`，但如何序列化为 multipart 文件没有设计细节。

## MEDIUM（文档质量/清晰度问题）

### M1. 命令数量引用不一致

`01-architecture-overview.md` §7：`"完整命令清单（38 采纳 + MVP + server 侧）"`
`07-commands/specs.md` 实际列表：MVP 7 + 高 3 + 中 17 + 低 16 = 43（含 `bible_memory_delete` 实际为 MCP tool）。

### M2. "永不 crash" vs "致命错误" 措辞

`03-daemon.md` §1：`"永不 crash"`。`startup.md` §4：列出"致命错误"。建议 startup.md 将"致命错误"改为"启动阻塞错误"。

### M3. `sessions` 表列名在不同文档中不一致

sqlite-schema.md 用 `created_at`/`closed_at`，upgrade.md 用 `started_at`/`topic_scope`/`buffered_chars`。

### M4. Phase 1 vs Phase 2 moment type 不对称缺少说明

Phase 1 prompt 含 `SESSION_START`，Phase 2 不含。设计合理但未解释。

### M5. F4 Phase 1 LLM 失败"连续失败 10 次"硬编码

`failure-paths.md` F4：`"连续失败 10 次 → daemon log error"`。此阈值不在 config 中。

### M6. Marketplace 命令语法为推测值

`10-deployment.md` 和 `upgrade.md` 中的 `npx @anthropic-ai/claude-code plugins install/update` 语法当前不存在，应标记 `[TBD]`。

### M7. `POST /session/end` 对已完成 session 返回 404

`http-api.md` §3.2 对已完成的 session 返回 404 `SESSION_NOT_FOUND`。幂等操作应返回 200 `{status: "already_completed"}`。

### M8. `daemon.pid` 文件的必要性存疑

`deployment.md` §8 列出 `daemon.pid`，但 daemon 的 run state 通过 HTTP health check 判断（`startup.md`），不依赖 PID 文件。

## LOW（建议改进）

1. **Token budget 估算精度**: `字符数/3` 对中英文混合偏差大，建议注明。未来可引入 `tiktoken`。
2. **Hint 去重不持久化**: `hint-system.md` 的 `_hint_tracker` 重启后丢失。建议文档标注为已知行为。
3. **E2E plugin packaging 步骤未细化**: `e2e.md` 未说明如何模拟 plugin 注册。
4. **`idx_moments_content_hash` 可能冗余**: SQLite UNIQUE 约束自带隐式索引。
5. **Config loader `model_validate` 对 partial JSON 的处理**: 若 JSON 缺字段可能抛异常。
